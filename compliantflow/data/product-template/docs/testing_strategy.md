## DHF Traceability

Every test that covers a regulated behaviour must link to a DHF item. CompliantFlow imports test results from JUnit XML on post-merge CI.

**Test ID convention:** Use a consistent format, e.g. `TC-SYS-001-001`.

**Required docstring format:**

```
def test_TC_SYS_001_001_my_behaviour():
    """
    TC-SYS-001-001: Brief description

    @test_id: TC-SYS-001-001
    @links: SYS-001
    """
```

**JUnit XML contract:**

```xml
<testcase name="test_TC_SYS_001_001_my_behaviour">
  <properties>
    <property name="compliantflow.id"    value="TC-SYS-001-001"/>
    <property name="compliantflow.links" value="SYS-001"/>
  </properties>
</testcase>
```

Tests without a `@links` tag produce orphaned test evidence and block the traceability gate.

---

## DHF Impact

New or modified tests require:

- A `TC` item in the DHF with `@links` to the relevant `SYS` or `SRS` item
- The test function name and docstring to match the TC ID
